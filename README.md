# CPU-EYE — C++ 到四种指令集的可视化 CPU 模拟器

把一段 C++ 代码编译成 **x86-32 / x86-64 / ARM32 / ARM64** 四种真实指令集的汇编，
再用指令级模拟器逐条执行，实时显示寄存器、标志位、栈内存、数据段、调用栈和数据通路的变化。

纯前端实现，零依赖，双击 `index.html` 即可运行。

**在线体验：https://chinadongnet.github.io/cpu-eye/**

## 目录结构

```

js/targets.js         四个 ISA 后端：指令的语义 + 汇编文本
js/codegen.js         代码生成：AST → 目标指令流
js/machine.js         指令级 CPU 模拟器（寄存器/内存/标志位/调用约定）

js/programs.js        7 个内置示例程序（含预期输出）

```

## 两个视图

**调试台** —— 源码、汇编、寄存器/栈内存三栏并排，逐条跟踪程序逻辑。

**CPU 示意图** —— 一张完整的处理器框图：PC、指令存储器、IR 指令寄存器、译码器、控制单元、
寄存器堆、ALU、标志寄存器、数据存储器、写回通路，以及地址总线 / 数据总线 / 控制总线。
每执行一条指令：

- 参与工作的部件与总线点亮，总线用流动虚线表示正在传输
- 地址总线、数据总线上显示当前真实的地址与数据
- 控制信号（RegWrite / ALUSrc / MemRead / MemWrite / Branch / MemToReg）随指令类型亮灭
- 寄存器堆中被读取的寄存器标绿、被写入的标橙
- 底部内存映射标出 PC 位置、函数分界、栈指针，以及本次访问的内存地址

例如一条 ARM64 的 `ldr w0, [x0]`，会依次点亮
PC → 指令存储器 → IR → 译码器 → 控制单元（MemRead、MemToReg 有效）→
ALU（算地址）→ 数据存储器 → 写回 MUX → 寄存器堆，
地址总线上显示 `0x0000efec`，数据总线上显示读出的值。

## 使用

| 操作 | 说明 |
| --- | --- |
| 视图切换 | 顶部 **调试台 / CPU 示意图**，两个视图共用同一套执行控制 |
| 编译装载（Ctrl+Enter） | 编译当前源码并复位 CPU |
| 单步（F10） | 执行一条机器指令，变化的寄存器/内存高亮闪烁 |
| 运行 / 暂停（F5） | 按所选速度连续执行（慢放 → 极速五档） |
| 点击汇编地址列 | 设置 / 取消断点 |
| 切换架构 | 自动用同一份源码重新编译，可直接对比不同 ISA |
| 四架构对比 | 一次编译并运行全部四种架构，比较指令数量与调用约定 |

## 自测

```bash
node test/run.js          # 7 个示例 × 4 种架构，比对输出
node build-artifact.js    # 重新生成网页部署版
```

自测同时验证编译器与模拟器：每个示例都带有预期输出，四种架构必须产生完全一致的结果。

## 支持的 C++ 子集

- 类型：`int`、`char`、`bool`、指针 `T*`、引用 `T&`、一维数组 `T a[N]`
- **类与结构体**：`class` / `struct` 的数据成员、成员函数、构造函数、`this`、`.` 与 `->`、
  对象数组、对象整体赋值、类外定义成员函数（`void A::f()`）、成员按真实规则对齐填充
- 全局变量（支持初始化列表）、局部变量、函数（支持递归）、引用传参
- 语句：`if/else`、`while`、`do-while`、`for`、`break`、`continue`、`return`
- 运算：`+ - * / %`、比较、`&& || !`、位运算 `& | ^ ~ << >>`、`++ --`、复合赋值、
  `&` 取地址、`*` 解引用、`sizeof`、C 风格类型转换 `(char*)p`
- 输出：`cout << 表达式 << endl;`（字符串常量按 UTF-8 存放，可直接打印中文），或 `print_int()` / `print_str()`
- `#include`、`using namespace std;`、`public:/private:` 会被忽略，可以照常书写

### 还没有实现的部分

继承与虚函数、模板、STL（`string` / `vector` / `cin`）、`new` / `delete`、析构函数、
运算符重载、函数与构造函数重载、异常、浮点数、多维数组、按值传递或返回对象。
遇到这些写法时编译器会给出明确提示，而不是含糊的语法错误。

## 实现要点

**代码生成**采用累加器 + 求值栈策略（与 chibicc 类似，相当于 `-O0`）：
二元运算先算右操作数压栈，再算左操作数并弹出到临时寄存器，结果始终留在累加器
（`rax` / `eax` / `x0` / `r0`）。这样生成的代码冗余但结构清晰，非常适合逐条观察。

**四种架构的差异是真实的**，不是换个寄存器名字：

| | x86-32 | x86-64 | ARM32 | ARM64 |
| --- | --- | --- | --- | --- |
| 调用约定 | cdecl，参数全部压栈 | System V，前 6 个走寄存器 | AAPCS，前 4 个走寄存器 | AAPCS64，前 8 个走寄存器 |
| 取模 | `cdq` + `idiv` | `cqo` + `idiv` | `sdiv` + `mls` | `sdiv` + `msub` |
| 取全局地址 | `mov eax, OFFSET g` | `lea rax, [rip + g]` | `ldr r0, =g` | `adrp` + `add :lo12:` |
| 条件置位 | `setcc` + `movzx` | `setcc` + `movzx` | 条件执行 `movlt/movge` | `cset` |
| 栈帧 | `push ebp` | `push rbp` | `push {fp, lr}` | `stp x29, x30, [sp,#-16]!` |

**模拟范围**：模拟器工作在指令语义层，忠实执行每条指令对寄存器、内存和标志位的影响，
遵循各架构真实的调用约定与栈帧布局；但不模拟指令编码字节、缓存、流水线冲突与乱序执行，
指令地址按 4 字节等距排列。内存为 64 KiB 平坦空间：数据段从 `0x1000` 开始，栈从 `0xF000` 向下生长。
